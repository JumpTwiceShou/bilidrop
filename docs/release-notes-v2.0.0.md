# BiliDrop v2.0.0 更新说明

这是一次完整重构版本。重点是让账号登录、任务识别、多账号挂机、奖励领取和本地存储
形成清晰、可恢复、适合长期运行的一套流程。

## 主要更新

### 全新界面与多账号运行

- 主界面重新组织为“账号、直播与任务、运行、任务进度”四个区域。
- 高级设置和运行日志移入独立的“设置与日志”窗口。
- 支持多个已保存账号和临时账号同时挂机；切换档案只切换管理视图，不会停止其他账号。
- 每个账号独立保存房间、任务、进度、运行状态和后台自动挂机状态。
- 账号选择器直接显示 UID、保存状态、登录状态和挂机状态。
- “应用到所有账号”开关可同时控制“开始/停止”和“后台自动挂机”。

### 扫码登录与安全存储

- 使用 Bilibili 官方二维码 API 在程序内扫码登录，不再为了获取 Cookie 打开浏览器。
- 同 UID 再次扫码会刷新原账号 Cookie，同时保留原备注。
- 临时账号不写入磁盘，程序退出后自动删除。
- 已保存 Cookie、通知地址和设置正文使用当前 Windows 用户的 DPAPI 加密。
- 账号、备注、设置统一保存在 `%LOCALAPPDATA%\BiliDrop\credentials.json`，程序目录不再
  产生配套 Cookie/设置文件。
- 自动兼容并迁移旧版本 `cookies.json`；验证成功后才归档旧文件。
- 账号覆盖、删除和同 UID 登录刷新前会建立加密轮转备份，降低误操作导致档案丢失的风险。

### 任务识别与进度

- 有房间号和 Cookie 即可开始挂机，任务识别不再是启动前置条件。
- 支持未开播直播间的任务发现，不会一直等待到浏览器超时。
- 自动识别当天可以进行的全部任务和所有奖励节点，不再只显示一个任务。
- 识别成功后立即刷新任务表格，无需再手动点击刷新。
- 兼容当前 EVA 页面数据、旧版页面结构和 `/x/task/totalv2` 网络响应。
- 直接请求失败时先使用真正无窗口的 Chrome/Edge 后台兜底，最后才启动用户可见浏览器。
- “识别当前任务”按钮在识别期间可直接切换为取消操作。
- 加入“守望先锋电竞”快捷入口，同时保留适用于所有活动房间的通用识别流程。

### 奖励进度与自动领取

- 每个 60/120/180/240 分钟等奖励节点独立显示完成、待领取和已领取状态。
- 使用奖励节点自己的 `sid` 领取，避免重复提交外层任务 ID。
- 按平台状态区分“已完成待领取”和“已经领取”，刷新后显示平台确认的最终状态。
- 达到节点后自动领取；手动领取仅作为失败兜底。
- 领奖和状态查询串行执行，并使用 1/5/15/60 分钟退避，避免持续请求导致接口限频。
- 任务完成与领奖结果可发送包含账号、直播间和任务名称的通知。

### 后台自动挂机

- 可定时检查任务：当前任务默认每 15 分钟检查，提前发现的未来任务每 60 分钟检查。
- 到达任务时间且直播开播后自动开始；当天任务全部完成并确认领奖后停止心跳，但继续
  守候新任务。
- 先开启后台自动挂机、后填写房间或识别任务时会立即唤醒检查。
- 停止后台自动会同时停止由它启动的挂机，不会误停用户手动开始的挂机。
- 后台自动挂机只在当前程序运行中有效；重新打开程序后默认关闭，不会自动启动挂机。

### 自适应并发与长期运行

- 默认并发改为 16，可选择“自动”或“固定”模式。
- 自动模式在需要追赶时使用 16 个会话；连续 3 分钟进度没有至少增加 16 时降为 2 个，
  并保持到下一组新任务，减少无效连接与风控风险。
- 后台自动检测到刚开始且初始进度为 0 的任务会先使用 2 个会话。
- 界面显示当前/目标会话数、重连次数、最近心跳和自动并发判断依据。
- 重构为一个进程一个 asyncio 后台，每个账号只有一个任务监控器。
- 任务刷新、领奖和后台自动停止统一由账号级控制器串行协调。

### Windows 桌面体验与打包

- 限制同一 Windows 用户只能运行一个实例；重复打开会显示已运行窗口。
- 最小化和关闭默认进入托盘，可在高级设置修改。
- 托盘使用带粉色底和深色描边的独立图标，在浅色任务栏上更清晰。
- 主窗口标题栏跟随程序深色主题。
- 默认构建为可独立运行的单文件 EXE，只打包程序需要的依赖。
- 支持 Telegram Bot、Gotify、Server 酱和企业微信通知。

## 升级说明

1. 完全退出旧程序，包括托盘中的后台进程。
2. 运行新的单文件 EXE。
3. 如果旧版 `cookies.json` 与新 EXE 位于同一目录，程序会自动加密迁移已保存账号。
4. 检查账号选择器中的 UID 和登录状态；失效账号请重新扫码登录。
5. 后台自动挂机不会随程序启动，需要每次运行后手动开启。

Windows DPAPI 加密数据只能由原 Windows 用户解密。将
`%LOCALAPPDATA%\BiliDrop\credentials.json` 复制到其他用户或设备不能直接使用。

## 验证范围

- 账号档案、旧 Cookie 迁移、DPAPI 存储和备份。
- QR 登录、同 UID 更新和多账号工作区切换。
- 任务发现、当天任务展开、奖励节点解析、领奖状态与限频退避。
- 后台自动挂机调度、停止语义和自适应并发。
- GUI 状态、托盘/单实例、通知内容和单文件资源。

平台任务和领奖接口属于外部服务，仍可能随 Bilibili 页面或接口调整而变化。
